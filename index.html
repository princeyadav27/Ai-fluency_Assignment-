Case 01 — Recall

01
AI-powered video search
The problemFinding a particular moment inside a long video is slow when the main option is manually scrubbing or searching only the transcript. I wanted a way to search for a moment by what was said, shown, or written.
What I didI designed Recall as a multimodal search system. The planned pipeline combines FFmpeg for video processing, Whisper for speech transcription, SigLIP for visual embeddings, OCR for text inside frames, PySceneDetect for scene boundaries, and FAISS for similarity search. I chose hybrid search because transcript-only search cannot reliably answer visual queries.
What came of itThe result is a product prototype direction that turns long videos into searchable speech, visual, and frame-text information. It gave me a concrete architecture for combining multiple AI models instead of treating an LLM as the whole solution.
What I would do differently next time: Measure search quality with a small set of real queries and compare transcript-only, visual-only, and hybrid ranking before expanding the system.

Case 02 — Computer Vision

02
Handstrike 3D — gesture-based computer vision
The problemI wanted to explore how a camera could become an interactive input instead of relying on a keyboard or controller. The goal was to turn recognizable hand movements into actions inside a game-like experience.
What I didI designed a computer-vision interaction flow around camera frames, hand landmark detection, and gesture interpretation. MediaPipe provides the hand landmarks, while application logic maps recognized gestures to actions. The important engineering decision was to keep the vision layer separate from the game/action layer so the interaction could be changed without rebuilding the detection pipeline.
What came of itThe project became a practical exploration of real-time computer vision and gesture-controlled interaction. It helped me understand that a useful CV application needs more than detection — it needs a reliable bridge from visual input to a clear user action.
Next improvement: Add a small gesture evaluation set and measure false positives, missed gestures, and response latency before expanding the interaction set.

Case 03 — Agentic AI Project

03
Building an AI agent as a system
The problemA normal chatbot can generate an answer, but real tasks may require the system to decide what to do, use tools, keep context, and recover when a step fails. I wanted to understand the engineering behind agents instead of treating an agent as only a prompt.
What I didI approached the agent as a software system: a model receives a goal, decides on the next step, calls an available tool when needed, observes the result, and continues until the task is complete. I focused on prompts, tool calling, context handling, agent loops, and the boundary between the model and the tools.
What came of itThe project helped me move from thinking of an AI agent as “just a prompt” to thinking about it as an orchestrated system made from models, tools, state, and control logic.
What I would do differently next time: Add repeatable evaluation tasks and failure cases so I can compare agent behavior instead of judging it only from a few successful runs.

Case 04 — Tourism Recommendation System

04
Hybrid ML tourism recommender
The problemGeneric travel suggestions do not account for the combination of destination, category, and budget that a particular traveler has in mind. I wanted to turn those inputs into a more targeted recommendation.
What I didI built a Python-based recommendation prototype using a tourism dataset, data processing, machine-learning-based ranking, and a Streamlit interface. The interface lets a user provide travel preferences and receive recommendations instead of manually searching through a large dataset.
What came of itI produced a working prototype that connects a recommendation model to a usable interface. The project gave me experience taking an ML idea beyond a notebook and exposing it through an application a user can interact with.
What I would do differently next time: Evaluate recommendation quality with a defined test set and user feedback rather than relying mainly on whether the interface produces plausible recommendations.

Case 05 — Partha

05
AI scholarship discovery agent
The problemStudents often have to search many university and scholarship websites to find opportunities that match their country, academic background, field, funding needs, and deadlines. The useful information is scattered and the eligibility rules are easy to miss.
What I didI designed Partha as an AI agent that starts with a student's profile and goals, searches scholarship sources, reasons about eligibility, and returns a focused set of opportunities. The core idea is to make the agent do more than answer questions: it should gather information, compare requirements, and explain why an opportunity may fit.
What came of itPartha became a practical agent concept for reducing the amount of manual scholarship research a student has to do. It also gave me a concrete problem for exploring tool use, structured student profiles, retrieval, source checking, and recommendation logic.
Next improvement: Connect Partha to verified scholarship sources and show the source, eligibility evidence, deadline, and last-checked date for every recommendation.
